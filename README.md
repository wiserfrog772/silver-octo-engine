# Crimson — Android

Мобильный музыкальный плеер Crimson с тёмно-красной темой и встроенным поиском музыки на YouTube.

## Возможности

- Импорт и локальное хранение аудиофайлов.
- Воспроизведение, поиск, очередь, перемотка, случайный порядок и повтор.
- Создание плейлистов, добавление и удаление треков в подборках с сохранением на устройстве.
- Изменение порядка треков перетаскиванием (мышь и сенсорный экран), командами вверх/вниз и вводом позиции; порядок автоматически сохраняется и синхронизируется с активной очередью воспроизведения.
- Длительность аудио определяется по метаданным в фоне после импорта, чтобы добавление файлов не блокировало интерфейс.
- Добавление следующих треков текущей медиатеки или плейлиста в очередь, начиная после текущей композиции.
- Полноэкранный плеер открывается нажатием на мини-плеер; свайп по обложке переключает треки.
- Поиск YouTube через встроенный youtubedl-android.
- Потоковое воспроизведение найденных треков с резервными клиентами YouTube.
- Скачивание лучшей доступной аудиодорожки без перекодирования; MP3 — отдельный резервный вариант через FFmpeg внутри APK.
- Поиск по названию плейлиста и трекам внутри него.
- Очистка технических приписок в названиях и исполнителях с сохранением значимых версий композиции.
- Нативное фоновое воспроизведение через Android ExoPlayer и MediaSession: пауза, следующий/предыдущий трек и перемотка работают независимо от активности WebView.
- Android foreground service сохраняет очередь и системное уведомление во время воспроизведения; ExoPlayer управляет CPU wake lock только на время проигрывания, а таймер прогресса интерфейса останавливается при сворачивании приложения.
- Импортированное аудио по необходимости переносится в приватные файлы приложения для доступа нативного плеера без зависимости от `blob:` URL WebView.
- Добавление загруженных аудиофайлов в медиатеку Crimson.
- Импорт, замена и удаление cookies.txt в формате Netscape; файл хранится в приватном каталоге приложения.
- Обложки треков, кэширование обложек и защита от повторного импорта одних и тех же файлов.
- Сортировка медиатеки: сначала новые, по названию или по исполнителю. Выбор запоминается, а порядок воспроизведения следует за выбранной сортировкой.

Радио не включено.

## Встроенный загрузчик Android

В APK используются:

- io.github.junkfood02.youtubedl-android:library:0.18.1 для поиска, получения аудиопотока и загрузки;
- io.github.junkfood02.youtubedl-android:ffmpeg:0.18.1 для преобразования аудио в MP3.

Загрузчик запускается по требованию. При первом поиске, прослушивании или скачивании библиотека извлекает встроенные runtime-компоненты во внутренний каталог приложения. Проверка статуса и открытие экрана не запускают извлечение.

Загрузчик автоматически выбирает **лучшую доступную аудиодорожку** с помощью `bestaudio`. Обычно это Opus или M4A, но кодек зависит от доступных потоков конкретного ролика. При выборе исходного формата аудио не перекодируется. Если исходную дорожку получить не удалось, используются альтернативная стратегия и затем резервное извлечение в MP3 через FFmpeg с наилучшим доступным качеством (`-q:a 0`). Видео не сохраняется. После скачивания проверяется размер и сигнатура аудиофайла; частичные `.part`/`.ytdl` файлы не считаются успешным результатом.

Для извлечения аудио включён QuickJS, а EJS-компоненты yt-dlp при необходимости загружаются с GitHub. Реализованы несколько попыток: штатное согласование клиента, запрос без импортированных cookies (если сессия конфликтует), резервный `web_safari` и MP3-ветка. Для потокового воспроизведения доступны штатный клиент, `web_safari` и Android. Это повышает устойчивость, но не гарантирует обход всех ограничений YouTube. Некоторые комбинации клиентов/форматов требуют PO Token; cookies сами по себе не заменяют его. Ошибка HTTP 403 может быть вызвана устаревшим runtime, истёкшими cookies, изменениями YouTube, PO Token или сетевым ограничением. Crimson показывает отдельное понятное сообщение и сохраняет подробности ошибки в Android logcat без вывода содержимого cookies.

Библиотека `youtubedl-android` содержит собственный yt-dlp runtime внутри APK. Поэтому Crimson обновляет именно runtime через стабильный канал библиотеки, а не системный `yt-dlp`. Автоматическая проверка выполняется при первом реальном действии с загрузчиком с ограничением по времени: после успеха — не чаще раза в 7 дней, после ошибки — повтор через 24 часа. В настройках доступна ручная проверка. В статусе отображаются версия runtime и версия обёртки отдельно. При отсутствии сети приложение продолжает использовать уже установленную версию.

Импортированный cookies.txt проверяется как Netscape-файл с действующими cookie для YouTube и копируется в приватное хранилище приложения с ограниченными правами доступа. Повторный импорт заменяет файл безопасно, с временным файлом и резервной копией; прежний файл сохраняется при ошибке замены. Можно удалить cookies или продолжать работу без них. Поиск, потоковое воспроизведение и загрузка используют сохранённый файл, когда он доступен. Cookies не обязательны для каждого ролика.

Перед записью извлекаются структурированные поля `track`, `title`, `artists`, `artist`, `album`, `release_date`, `genre` и другие доступные поля yt-dlp. Служебные приписки вроде `Official Audio`, `Lyrics`, `Visualizer`, `HD` и разрешения удаляются из названий и тегов; значимые версии (`Remix`, `Live Version`, `Acoustic Version`, `Instrumental`, `Remastered`, `Radio Edit`, `Extended Mix`) сохраняются. В аудиофайл встраиваются метаданные и обложка, если источник их предоставляет. Имя формируется как `Artist - Track.ext`, а при неизвестном исполнителе — `Track.ext`. Год и жанр не выдумываются, если извлечь их нельзя.

На Android 10 и новее готовые файлы сохраняются в общую папку **Music/Crimson Downloads** через MediaStore. Если в настройках выбрана собственная папка загрузок, приложение использует её. На Android ниже 10 используется доступный приложению каталог Music.

### Архитектура APK

Сборка включает только ABI **arm64-v8a**, чтобы не упаковывать дополнительные копии больших нативных runtime-компонентов. Устройства только с 32-битным ARM (armeabi-v7a) или x86 не поддерживаются.

## Скачать APK

Рабочий процесс загружает отладочный APK как артефакт сборки в [GitHub Actions](https://github.com/goofyplanets/animated-sniffle/actions) (хранится 14 дней). Публикация в GitHub Releases не настроена.

## Сборка локально

Требуются Node.js 22+, Java 21 и Android SDK.

    npm install
    npx cap add android
    npm run prepare:android
    npx cap sync android
    cd android
    ./gradlew assembleDebug

Файл: android/app/build/outputs/apk/debug/app-debug.apk.

## Архитектура и проверки

`www/app.js` остаётся точкой сборки интерфейса и координации событий; вспомогательная логика вынесена в `www/modules/`: `storage.mjs` (IndexedDB и настройки), `player.mjs` (очередь и фильтрация медиатеки), `playlist-order.mjs` (атомарное изменение порядка треков в плейлистах), `youtube.mjs` (результаты, ошибки и cookies), `music-metadata.mjs` (очистка и нормализация метаданных), `ui.mjs` (общие UI-функции). Нативная часть загрузчика находится в `YtDlpPlugin.java`.

    npm run check   # синтаксис JavaScript
    npm test        # модульные и статические проверки проекта

Тесты не требуют внешних зависимостей помимо Node.js 22+ и запускаются в CI перед сборкой APK. На момент этой версии workflow устанавливает зависимости через `npm install`: lock-файл не включён. Для перехода на `npm ci` нужно сформировать и проверить `package-lock.json` в окружении с доступом к npm registry.

## Совместимость и технические идентификаторы

Приложение переименовано из «Localify Crimson» в **Crimson**. Часть технических идентификаторов намеренно сохранена, чтобы обновление не потеряло данные пользователей и не превратилось в установку «другого» приложения:

- `applicationId` и Java-пакет `com.localify.crimson` (в том числе intent-actions): при смене Android считает APK новым приложением, и данные не переносятся;
- имя IndexedDB `localify-crimson-mobile` (медиатека), SharedPreferences `localify_storage` и `localify_native_playback`, каталог `LocalifyTracks` во внутренней памяти, файл `localify_diagnostics.log`, id канала уведомлений `localify_music_playback`;
- ключи `localify.mobile.*` в localStorage читаются один раз и переносятся в `crimson.mobile.*`.

Новые загрузки сохраняются в **Music/Crimson Downloads**; файлы из прежней папки остаются на месте и по-прежнему открываются из медиатеки.

### Управление действиями трека и перемотка

- В медиатеке действия с композицией доступны через меню `⋮`; добавление в очередь остаётся отдельным действием.
- Свайп вправо по строке показывает подсказку «Добавить в плейлист». При первом использовании открывается выбор плейлиста; выбранная подборка запоминается для следующих быстрых добавлений. Повторное добавление одного ID блокируется; при быстром добавлении через свайп в уведомлении есть действие «Отменить».
- Свайп распознаётся только при преобладающем горизонтальном движении вправо. Вертикальная прокрутка и ручка Drag & Drop порядка плейлиста исключены из этого жеста.
- Полоска прогресса отображается в компактном и полноэкранном плеере. Она синхронизируется с HTMLAudioElement в браузере и с `CrimsonPlayback.seekTo` на Android; для неизвестной длительности перемотка отключается до появления достоверного значения.
