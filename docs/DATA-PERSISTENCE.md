# Сохранность данных Crimson

## Где что хранится
| Данные | Место | Переживает переустановку? |
|---|---|---|
| Плейлисты, порядок, очередь и часть настроек | `localStorage` WebView (контрольная сумма + предыдущая копия `.bak`) и JSON-снимок резервной копии | Локальное хранилище — нет; снимок — да, если доступна внешняя копия или Android Auto Backup |
| Резервная копия (основная + до 5 архивных) | `files/backup/` приложения | Да, если включён Google Backup (правила `crimson_backup_rules.xml`) |
| Зеркало последней резервной копии | `Crimson Backup/crimson-backup.json` внутри каждой выбранной папки медиатеки и загрузок | Да, вне данных приложения; достаточно повторно выбрать одну из этих папок |
| Папки плейлистов | `<название> [<8 hex ID>]/crimson-playlist.json` прямо в первой доступной пользовательской папке | Да, содержит стабильный ID, последовательность и ссылки на треки |
| Ручной экспорт | Файл, выбранный пользователем (Настройки → Экспорт плейлистов) | Да |
| Индекс музыкальной библиотеки | IndexedDB WebView (схема v2, индексы) | Сам индекс — нет; заново строится сканированием выбранной папки |
| Разрешения на пользовательские папки | Android SAF URI в `SharedPreferences` | После полного удаления приложения могут быть сброшены; папку нужно выбрать повторно |

Снимок резервной копии включает плейлисты и ссылки на треки, очередь, выбранную сортировку, лимит параллельных загрузок и режим уменьшенной анимации. Само содержимое музыкальной библиотеки резервируется не целиком: аудио остаётся в пользовательской папке, а индекс строится повторным сканированием.

## Как работает восстановление
Плейлист хранит не только `trackIds`, но и ссылки `refs` (название, исполнитель, источник, длительность).
После переустановки id треков меняются, поэтому плейлисты сопоставляются с заново отсканированной
библиотекой: `id → источник → videoId → исполнитель+название`. Пока трек не найден, ссылка ждёт и
подтягивается после сканирования. Копия выбирается автоматически: самая свежая исправная из всех источников.

## Удаление приложения
- `android:hasFragileUserData="true"` — Android 10+ спросит, сохранить ли данные при удалении.
- Если данные сохранены и APK подписан тем же ключом, внутренние данные приложения могут вернуться как были.
- Debug-сборки из CI подписываются случайным ключом: поверх друг друга и «с сохранением данных» они не ставятся.
  Для надёжности используй постоянный release-keystore.
- Если приложение удалено полностью: заново выбери ранее использовавшуюся папку медиатеки или загрузок. Crimson прочитает `Crimson Backup` из выбранного корня и восстановит плейлисты, очередь и сохранённые настройки; затем просканируй музыкальную папку, чтобы восстановить индекс.
- «Удалить все данные…» в настройках стирает данные приложения и все копии (с двойным подтверждением).

## Ограничения
- Файлы музыки в выбранной папке никогда не удаляются.
- Auto Backup зависит от настроек Google на устройстве и не гарантирован. Внешнее зеркало — последняя валидная копия, которая перезаписывается после очередного сохранения; оно не является версионированной историей.
- Разрешение Android SAF хранится отдельно от JSON-снимка. После полного удаления приложения пользователь должен повторно выбрать папку; без такого разрешения приложение не может прочитать её зеркало.

## Плейлисты-папки без физических копий аудио
- Создание, переименование, изменение состава или порядка плейлиста записывается в `<название> [<8 hex ID>]/crimson-playlist.json` (автоматически через 2,5 сек. после изменения).
- В манифесте хранится стабильный ID плейлиста, порядок композиций и ссылки на треки. Само аудио остаётся в основном месте хранения; добавление композиции в несколько плейлистов не создаёт копии в каждой папке.
- Android Storage Access Framework (`DocumentFile`) не предоставляет переносимый механизм hard link или symlink в пользовательских папках. Поэтому папки плейлистов содержат манифест-ссылки, а не дублирующие аудиофайлы.
- Старые копии, созданные прежними версиями Crimson, удаляются при следующей синхронизации только если старый манифест помечает их как созданные приложением и SHA-256 побайтно совпадает с доступным оригиналом. Изменённые или непроверяемые файлы сохраняются.
- Аудиофайлы, вручную добавленные пользователем в папку плейлиста, обнаруживаются при чтении папок, импортируются в общую библиотеку и добавляются только в соответствующий плейлист.
- Ссылки на треки без постоянного `nativePath` (например, импортированные только как `blob:`) также остаются в манифесте, но сам временный аудиопоток не может быть восстановлен после удаления данных WebView. Для гарантированного восстановления аудио файл нужно сохранить в постоянную музыкальную папку.
- После переустановки: выбери ту же пользовательскую папку → просканируй библиотеку → Crimson восстановит ID и порядок из манифестов и сопоставит композиции с общей библиотекой. Для отсутствующих в библиотеке ручных файлов используется содержимое папки плейлиста.
- Удаление плейлиста удаляет его манифест и пустую папку, но не удаляет аудио и другие пользовательские файлы.

## Ограничения текущего импорта
- При импорте файла через WebView на Android приложение может создавать приватную рабочую копию в `LocalifyTracks`, поскольку нативному ExoPlayer нельзя передать временный `blob:` URL. Это отдельный механизм импорта/воспроизведения; он не создаёт копии при добавлении трека в разные плейлисты.


## Физические папки плейлистов (обновление)

Новые папки создаются непосредственно в выбранном корне медиатеки (или папке загрузок, если корень медиатеки не выбран) и называются `Название [короткий ID]`. Внутри хранится только JSON-манифест с ID плейлиста, порядком треков и ссылками на канонические записи библиотеки. Аудиофайлы не копируются. Старый контейнер `Crimson Playlists/` читается для миграции; принадлежащие приложению старые копии удаляются только после проверки контрольной суммы.
